1. 專案背景與痛點分析 (Background & Pain Points)

在企業、工作坊或各類專案的日常營運中，財務人員（特別是出納）在每月或每週發放承攬人員、臨時工、外包商的現金薪資時，經常面臨以下作業痛點：

1. 手動拆鈔耗時且極易出錯 為了將薪資放入實體薪資袋，財務必須將每位員工的「應領金額」拆解為適當的「千元鈔、五百元鈔、百元鈔、五十元硬幣、十元硬幣、五元硬幣、一元硬幣」組合。手動使用計算機或 Excel 容易因為漏看或加總失誤，導致實體發放金額與帳面不符。

2. 臨櫃兌換（換錢）缺乏精確總表 出納在前往銀行臨櫃兌換鈔幣前，必須彙整出一份「銀行換錢總表」（例如：總共需要 1000 元鈔幾張、50 元硬幣幾個等）。若沒有自動化工具，常需在紙上重複核對加總，耗費巨大心力。

3. 複製格式混亂導致系統解析失敗 財務人員的數據大多來自 Google Sheets 或 Excel。當直接複製兩欄（姓名、金額）並貼上到一般網頁工具時，常因「千分位逗號（,）」、「貨幣符號（$）」、「全形/半形逗號或 Tab 鍵」的混用，導致工具出錯甚至停止運作。

4. 高度敏感的財務資安疑慮 薪資、承攬費用與個人姓名屬於極度敏感的個人資料（個資）。現行市面上許多線上工具會將輸入的資料傳送至後端伺服器進行處理，這在企業稽核與財務資安上是「絕對的禁忌」。

產品使命與核心定位

「幫你算兌 Money Snap」 是一款專為財務人員打造的**「財務護身符」。其定位為純本地端運作、100% 隱私安全、極致容錯、支援一鍵快速對帳與截圖匯出**的輕量級網頁工具。

2. 產品核心價值與設計原則 (Design Principles)

• 數據絕對安全 (Zero Net Leak)：承諾 100% 於用戶瀏覽器前端（Client-side）進行運算。嚴格禁止任何外發業務相關網路請求（No API/XHR/Fetch），確保個資絕不離地。註：專案內嵌 Google Analytics 僅用於匿名流量與功能使用統計，絕不涉及任何業務資料傳輸。

• 智慧容錯與極佳體驗 (Smart Parsing & Autofocus)：極大化相容試算表貼上的各種混亂格式，並在資料出錯時「精確指出行號並自動反白高亮」，引導使用者快速排除問題。

• 雙重對帳零死角 (Double-Entry Verification)：系統在產出報表前，自動比對「輸入總額」與「面額拆解加總」，杜絕任何因浮點數運算或演算法漏洞導致的差額。

• 版面美觀與高度整合 (Aesthetics & Clean Design)：UI 佈局精準嚴格，符合財務對帳之正式感。匯出圖片時自動隱藏操作按鈕，呈現最乾淨、無干擾的實體報表。

3. 核心功能規格 (Functional Requirements)

3.1 智慧格式解析 (Smart Input Parser)

• 需求描述：提供一個大型文字輸入框（Textarea），允許使用者直接從 Excel/Google Sheets 複製兩欄資料（姓名與金額）並貼上，由系統自動解析。

• 功能規則：

    1. 多重分隔符支援：能自動識別並切割每一行。分割基準依序為：Tab 鍵 (\t)、半形逗號 (,)、全形逗號 (，)。

    2. 空行與空白容錯：自動過濾純空白行，不計入解析筆數，避免產生空數據。

    3. 金額符號自動清洗：自動移除金額字串中含有的貨幣符號（如 $, ￥, €, £）及千分位分隔符（如 1,000 或 1，000），再行轉換為數值。

    4. 欄位防呆限制：單行必須剛好包含「姓名」與「合法金額」兩個欄位。若有以下狀況，視為格式錯誤：

		• 只有姓名，無金額（如：王小明）。

		• 有多於兩個分割欄位（如：王小明,1000,獎金）。

		• 金額欄位清洗後，無法轉成正整數/正浮點數（如：王小明, 一千元）。

3.2 錯誤精確高亮定位 (Error Highlight)

• 需求描述：若輸入資料中存在上述格式錯誤，系統不得繼續運算，且必須提供精確的錯誤指引。

• 功能規則：

    1. 行號提示：於輸入框下方顯示醒目的紅色 Alert，說明「第 X 行格式錯誤（原因：...）」。

    2. 自動反白高亮 (Selection Range)：系統應自動聚焦（Focus）至 Textarea，並將出錯的那一行文字自動選取、反白（Highlight），使用戶能直接打字修正，無需自行手動尋找。

3.3 姓名正規化與同名加總 (Name Normalization & Grouping)

• 需求描述：考量到同一位承攬人員可能在該期有複數筆工作項目（例如：王小明有「車馬費 1200」與「講稿費 3500」兩筆記錄），系統必須自動進行同名合併。

• 功能規則：

    1. 姓名正規化 (Normalization)：

		• 將全形英文字母、數字轉換為半形。

		• 去除姓名首尾之空白字元。

		• 將姓名內部的連續多個空白縮減為單一空格（如 張  小明 轉換為 張 小明）。

    2. 合併邏輯：

		• 以正規化後的「小寫與統一空格」之姓名作為 Key 進行 Group & Sum。

		• 最終輸出時，姓名顯示欄位應採用該人員「第一次出現時」的正規化姓名格式。

    3. 穩定排序：合併後的名單，輸出時應依「姓名」進行字典排序（A-Z / 中文拼音筆劃排序），確保每次計算的結果順序穩定一致。

3.4 最佳面額拆解演算法 (Denomination Greedy Algorithm)

• 需求描述：針對合併後的每個人應領總金額，自動計算最少鈔幣數。

• 支援面額：台灣常用法定貨幣面額：1000元、500元、100元、50元、10元、5元、1元。

• 演算法規則：採用貪婪演算法（Greedy Algorithm），從 1000 元面額依序除算、遞減，求出各面額所需之「張數」或「個數」。

3.5 雙重對帳校驗機制 (Double-Entry Verification)

• 需求描述：此為防止程式運算錯誤或浮點數失準的「財務安全閥」。

• 驗證公式：


$$S_{input} = \sum \text{所有解析成功行數之原始輸入金額}$$

$$S_{breakdown} = \sum \text{個人明細中所有面額} \times \text{對應數量}$$

• 控制邏輯：

    1. 系統在算畢時，若發現 ‭$S_{input} \neq S_{breakdown}$‬，需立刻停止報表呈現。

    2. 顯示紅色重大系統異常錯誤提示：「輸入總額與面額拆解總額不一致，請聯絡開發人員人工核對」。

    3. 立即禁用（Disable）「匯出圖片」按鈕，防範不實數據流出。

3.6 報表產出與乾淨圖片匯出 (Image Exporting & Snap Optimization)

• 需求描述：計算完成後，即時生成直觀、可供核對並保存的財務報表。

• 報表結構：

	• 銀行領款總需求表：橫向/縱向表格，列出各面額所需之「總張數/總個數」以及「該面額之總金額」，並提供「總需求大計（整數金額）」。

	• 個人領現明細表：清單表格，包含：姓名 | 應領金額 | 各面額拆解明細 (以精美 Badge 呈現)，並於表頭或表尾標註「計算時間：YYYY-MM-DD HH:MM:SS」。

• 圖片匯出（Money Snap 特色）：

    1. 點擊「匯出圖片」後，自動將完整的報表區塊轉換成圖片檔（PNG 格式）並觸發下載。

    2. 拍照優化模式：在截圖瞬間，系統必須自動將「清除所有資料」、「計算與統計」與「匯出圖片本身」等按鈕暫時隱藏，僅保留無按鈕干擾的純淨財務對帳單，並於截圖完成後自動還原按鈕顯示。

    3. 快門特效：匯出時提供短暫的快門閃爍動畫（Flash Effect），給予使用者明確的操作反饋。

3.7 本地狀態保存 (Local Persistence)

• 需求描述：防止財務人員不小心重整網頁、瀏覽器當機或不慎關閉分頁導致手動修正後的資料遺失。

• 功能規則：

	• 每次成功計算後，系統自動將「原始輸入文字」與「運算結果狀態」寫入瀏覽器 LocalStorage。

	• 網頁載入時，自動偵測並回復上次的輸入與計算狀態，確保工作不中斷。

4. 使用者介面 (UI) 與版面佈局規劃

UI 介面遵循極簡、高對比、護眼且利於對帳的原則。整體頁面分為兩大層次：主要內容白色區塊 (Card Body) 與 外層低飽和灰色背景 (Page Background)。

4.1 頁面佈局順序 (Page Layout Hierarchy)

1. 大標題列 (Header) * 顯示文字：幫你算兌 Money Snap - 兌幣計算機（此處依需求移除版本號）。

	• 標題右側對齊位置：設置一組【匯出圖片】按鈕。

2. 格式提示小字 (Help Text) * 以灰色、較小字級呈現，說明輸入規範（支援 Tab、全半形逗號、自動過濾千分位與貨幣符號）。

3. 主要資料輸入區 (White Block - Input Area) * 大容量文字輸入框（預設 Placeholder 提供範例指引）。

	• 輸入框下方置中並排兩個按鈕：【清除所有資料】（灰/紅色柔和色系） 與 【計算與統計】（品牌主色調、醒目）。

4. 輸出結果區 (Output Dashboard) * 計算完成後由下方滑出或淡入顯示。

	• 子區塊 A：銀行領款總需求表。

	• 子區塊 B：個人領現明細表（包含「計算時間」戳記）。

5. 免責聲明區 (Disclaimer Block) * 緊貼於白色主要內容區下方，採用灰色背景，說明「本工具不傳輸任何資料，所有計算均在瀏覽器端完成」。

6. 頁尾 Footer (Single Line & Version) * 設有一條優雅的水平分割線。

	• 第一行（左右分散佈局）：

		• 左側顯示：© 2026 Money Snap · 開發者：tzuchienkao | MIT License

		• 右側留白或與左側對稱分散。

	• 第二行（水平置中）：

		• 顯示 Version 0.1.0。

5. 安全性與隱私防護標準 (Security Standards)

為確保本工具可以作為財務人員的安全防毒護身符，系統必須嚴格遵守以下資安準則：

1. 零外部網路調用 (Zero API Calls) * 程式碼中嚴禁使用 fetch、XMLHttpRequest、navigator.sendBeacon、或任何可能將資料傳送到外部網域的第三方 SDK。

	• 所有計算、加總、面額拆分、檔案下載（html2canvas）必須 100% 在前端記憶體（In-Memory）完成。

2. 無外部圖片或未受信任資源 * 不得加載任何外部不受信任來源的圖片、廣告代碼或追蹤碼，避免 XSS (跨站腳本攻擊) 導致輸入框內容被竊取。

3. 安全審查聲明 * 本專案原始碼開放（MIT License），財務管理人員、資安工程師隨時可以透過瀏覽器的「開發者工具 (Network Tab)」對其進行安全稽核，證明在輸入、運算與匯出過程中，網路傳輸量為零。
