## 4. 貨幣符號驗證規則

貨幣符號相關邏輯集中於 `src/currency.js`。

### 4.1 已知符號集合

- 多字元優先處理：`NT$`, `HK$`
- 已知單字元集合：`$`, `¥`, `€`, `฿`, `₩`, `￡`

### 4.2 驗證規則

1. 使用者可輸入**純數字**，不必一定附帶符號。
2. 若輸入帶有符號，必須符合目前選擇幣別的允許列表：
   - `TWD`：`NT$`、`$`
   - `USD`：`$`
   - `JPY`：`¥`
   - `KRW`：`₩`
   - `CNY`：`¥`
   - `HKD`：`HK$`
   - `EUR`：`€`
   - `THB`：`฿`
3. `detectCurrencySymbolMismatch()` 會先處理 `NT$`、`HK$`，避免被其中的 `$` 誤判。
4. 符號不符時，解析立即失敗並回傳 `CURRENCY_SYMBOL_MISMATCH`。
5. 允許符號會由 `stripAllowedCurrencySymbols()` 移除，再進入數值驗證。
6. 非允許且非已知的特殊字元通常不會被自動清洗，會在後續數值格式檢查階段失敗。

## 5. 輸入模式與解析行為

輸入解析由 `src/parser.js` 的 `parseInput()` 負責。

### 5.1 含姓名模式

- 啟用條件：`#hasNameFlag` 勾選
- 支援分隔：
  - Tab
  - 半形逗號 `,`
  - 全形逗號 `，`
- 解析規則：
  - 第一個分隔符前視為姓名
  - 其後視為金額
  - 若姓名或金額空白，回傳對應錯誤
- 同名項目在後續會由 `aggregateEntries()` 做標準化與加總

### 5.2 純金額模式

- 啟用條件：`#hasNameFlag` 取消勾選
- 每行僅輸入金額
- 系統自動產生名稱：
  - `zh-TW`：`項目 #1`
  - `en-US`：`Item #1`

### 5.3 數值解析規則

- 先移除允許的貨幣符號
- 再移除千分位逗號、全形逗號與空白
- 接受：
  - 整數
  - 小數（僅限該幣別允許位數）
  - 負數（**文字輸入 parser 支援；CSV 匯入 parser 不接受負數**）
- 限制：
  - 最多 `1000` 筆
  - 每筆金額整數部分上限 `999,999`
- 0 小數位幣別以 `BigInt` 儲存整數值
- 有小數位幣別以**最小貨幣單位的 `BigInt`** 儲存（如 USD 以 cents）

### 5.4 姓名聚合規則

`src/aggregator.js` 的 `aggregateEntries()` 具備以下行為：

- 全形轉半形
- 移除控制字元與零寬字元
- trim 前後空白
- 多重空白壓縮成單一空白
- 以 `toLowerCase()` 做 case-insensitive 合併
- 保留第一次出現名稱作為輸出名
- 預設依名稱排序，確保輸出穩定

## 6. CSV 行為

CSV 行為由 `src/csv.js` 負責，依賴頁面載入的 PapaParse CDN。

### 6.1 CSV 匯入

- UI 入口：
  - `CSV 檔案匯入`
  - 隱藏型 `input[type=file]`
- 檔案限制：
  - 僅接受 `.csv`
  - 檔案大小上限 `1MB`
- 解析行為：
  - `skipEmptyLines: true`
  - UTF-8 編碼
  - 自動略過常見表頭關鍵字：
    - `姓名`、`名字`、`name`
    - `金額`、`薪資`、`應發`
    - `amount`、`salary`
- 含姓名模式：
  - 使用第 1 欄姓名、第 2 欄金額
  - 同名時直接在 CSV parse 階段先合併
- 純金額模式：
  - 使用第 1 欄金額
  - 自動編號名稱
- 驗證：
  - 金額格式必須為非負數字 / 小數
  - 小數位數需符合幣別
  - 整數部分不可超過 `999,999`
  - 錯誤時彙整前 5 筆顯示
- 成功後行為：
  - 轉寫回 textarea
  - 顯示 `資料來源由 {file} 匯入`
  - 自動執行 `parseAndCompute()`

### 6.2 CSV 範例下載

- 依目前語系與幣別產生對應範例
- 內容包含表頭與 3 筆範例資料
- 使用 UTF-8 BOM，降低 Excel 開啟亂碼風險
- 檔名格式：
  - `zh-TW`：`MoneySnap_{CODE}_匯入範例.csv`
  - `en-US`：`MoneySnap_{CODE}_sample.csv`

### 6.3 CSV 匯出

- 需先有 `latestSummaryResult`
- 依目前幣別匯出：
  - 姓名欄
  - 金額欄
  - 各面額欄
  - 總計列
- 採 `Papa.unparse()` 產生 RFC 4180 格式
- 使用 UTF-8 BOM
- 檔名格式：
  - `zh-TW`：`MoneySnap_{CODE}_面額明細_YYYYMMDD.csv`
  - `en-US`：`MoneySnap_{CODE}_breakdown_YYYYMMDD.csv`

### 6.4 CSV 實作注意事項

- 匯出的金額使用**格式化後字串**，不是原始 minor-unit 整數。
- `exportResultsToCsv()` 的欄位來源為 `defaultBanknotes + defaultCoins`；若幣別存在重複面額（如 CNY/HKD），物件鍵會自然去重並沿用第一次插入順序。
- `tests/export_test.mjs` 存在，但**目前 `npm test` 不會執行它**。

## 7. 面額設定行為

面額設定由 `src/denomination-config.js` 與 `src/app.js` 共同負責。

### 7.1 狀態模型

儲存鍵：`money_snap_multi_currency_config_v5`

主要結構：

- `language`
- `currency`
- `saveAsDefault`
- `currencies.{code}.isCustomEnabled`
- `currencies.{code}.activeDenominations`

### 7.2 UI 行為

- `啟用自訂面額設定` 為主開關
- 關閉時：
  - 隱藏自訂面額面板
  - 顯示預設面額提示
  - 計算採用 `getCurrencyDenominations(currentCurrency)` 全集合
- 開啟時：
  - 顯示紙鈔/硬幣區塊
  - 可逐項勾選面額
  - 可使用紙鈔/硬幣各自的全選 checkbox
  - 計算採用 `getActiveDenominations(currentCurrency)`

### 7.3 防呆與殘額

- 至少要保留一種面額
- 若取消最後一個面額，UI 會立即阻止並顯示 toast
- 若選擇的面額組合無法完整拆解：
  - `breakdownAmount()` 不直接拋錯
  - 會保留 `remainder`
  - 之後由 `verifyDoubleEntry()` 擋下輸出

### 7.4 計算與對帳

- `computeBankTotals()` 逐人拆解面額並彙總
- `verifyDoubleEntry()` 比較：
  - `inputSum`
  - `bank.totalAmount`
- 對帳失敗時：
  - 清空畫面結果
  - 顯示本地化錯誤訊息
  - 禁用匯出

## 8. 匯出與複製行為

### 8.1 一鍵複製銀行領款單

- 優先使用 `navigator.clipboard.writeText`
- 不支援時 fallback 到 `document.execCommand('copy')`
- 內容包含：
  - 總金額
  - 總筆數
  - 目前計算所用面額的銀行總需求

### 8.2 圖片匯出

- 依賴 `html2canvas` CDN
- 匯出時會：
  - 隱藏按鈕 / CSV 區 / 自訂面額區 / 語系與幣別切換
  - 將 textarea 轉成純文字區塊
  - 顯示時間浮水印
  - 下載 PNG
- 僅下載圖片，不會額外上傳或留存檔案

### 8.3 可匯出條件

- `isDataValidForExport === true`
- 代表：
  - parse 成功
  - 單人上限驗證通過
  - 總額上限驗證通過
  - 雙重對帳驗證通過

### 9.3 GA 事件限制

`sendGaEvent()` 的設計目標為只送出匿名互動：

- 常見事件：
  - `change_language`
  - `change_currency`
  - `toggle_custom_denomination`
  - `toggle_name_mode`
  - `click_import_csv`
  - `click_export_csv`
  - `click_export_image`
  - `click_copy_bank`

## 13. 實作狀態摘要

v0.5.0 目前已是**多幣別、雙語、本地計算、可匯入匯出**的前端工具；文件撰寫時的規格應以實際程式碼為準，尤其要注意以下兩點：

1. **未開啟自訂面額時，計算使用的是該幣別完整可用面額集合。**
2. **CNY/HKD 的重複面額已透過去重與紙鈔優先策略處理。**

以上為目前程式碼庫可驗證的實作狀態。
