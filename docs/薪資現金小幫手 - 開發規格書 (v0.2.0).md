1. 專案目標與核心價值

打造一款輕量、高效且極致安全的現金薪資發放輔助工具。系統支援彈性輸入解析、跨項目同名加總、貪婪演算法面額拆解，並即時產出「銀行領款清單」與「個人薪資袋面額明細」，大幅降低財務人員的人為錯誤。

2. 技術選型與資安架構 (Tech Stack & Security)

2.1 技術選型

• 前端核心 (Core): Pure Vanilla JavaScript (ES6+), HTML5, CSS3

• UI 框架: Tailwind CSS (Via CDN / Compiled bundle)

• 圖像處理: html2canvas (純本地 DOM 轉圖片)

• 數據持久化: localStorage (僅記憶用戶設定與輸入歷史)

• 應用程式封裝: PWA (Web App Manifest + Service Worker sw.js Cache-First 離線存取)

• 成效追蹤: Google Analytics 4 (僅追蹤不含 PII 之行為事件)

2.2 資安防護機制 (財務人員護身符)

• 完全本地端運算 (Client-side Sandbox): 所有文字解析、面額拆解與對帳邏輯均於瀏覽器（客戶端）執行。

• 零數據外洩: 原始碼中嚴禁含有任何將使用者薪資數據對外發送之 fetch()、axios 或 XMLHttpRequest 請求。

• 安全截圖: html2canvas 於本地 Canvas 執行，產出 DataURL 供下載，不經過伺服器處理。

4. 核心演算法與邏輯細節

4.1 雙模式文本解析與同名加總 (Dual-Mode Text Parser)

系統需支援兩種解析模式（由 UI 開關「貼上資料包含姓名欄位」決定）：

• 含姓名模式 (hasNameFlag = true): 每行支援 TAB (\t) 或逗號 (,) 分隔。若出現同名者，自動進行金額加總。

• 純金額模式 (hasNameFlag = false): 每行僅讀取數字，姓名自動帶入 項目 #1, 項目 #2 ...。

[javascript]
/**
 * 雙模式文本解析器
 * @param {string} text - 輸入框原始文字
 * @param {boolean} hasNameFlag - 是否包含姓名欄位
 * @returns {ParsedItem[]}
 */
function parseInputText(text, hasNameFlag) {
  const lines = text.split('\n');
  const nameMap = new Map();
  let itemCounter = 1;

  lines.forEach((line) => {
    const trimmed = line.trim();
    if (!trimmed) return;

    let name = '';
    let amount = 0;

    if (hasNameFlag) {
      // 支援 TAB 或 逗號 分隔
      const parts = trimmed.replace('\t', ',').split(',');
      if (parts.length >= 2) {
        name = parts[0].trim();
        // 清除金額中的非數字字元 (如千分位逗號)
        amount = parseInt(parts[1].replace(/[^\d]/g, ''), 10) || 0;
      }
    } else {
      name = `項目 #${itemCounter++}`;
      amount = parseInt(trimmed.replace(/[^\d]/g, ''), 10) || 0;
    }

    if (amount > 0) {
      if (nameMap.has(name)) {
        nameMap.set(name, nameMap.get(name) + amount);
      } else {
        nameMap.set(name, amount);
      }
    }
  });

  const items = [];
  let idIndex = 0;
  nameMap.forEach((amount, name) => {
    items.push({ id: `item-${idIndex++}`, name, amount });
  });

  return items;
}


4.2 貪婪面額拆解 (Greedy Algorithm)

拆解順序由大至小（1000 -> 500 -> 100 -> 50 -> 10 -> 5 -> 1），採整除取商數與餘數計算。

[javascript]
const DENOMINATIONS = [1000, 500, 100, 50, 10, 5, 1];

function calculateBreakdown(amount) {
  let remaining = amount;
  const result = {};

  DENOMINATIONS.forEach(d => {
    const count = Math.floor(remaining / d);
    result[d] = count;
    remaining %= d;
  });

  return result;
}


4.3 雙重對帳與數據容錯機制 (Double-Entry Verification)

計算完成後，強制比對「原始輸入總金額」與「面額加總金額」。若不符合，阻斷輸出並提示紅色錯誤。

[javascript]
function verifyDoubleEntry(parsedItems, summaryResult) {
  const sumInput = parsedItems.reduce((acc, cur) => acc + cur.amount, 0);
  let sumBreakdown = 0;

  Object.entries(summaryResult.bankTotals).forEach(([denom, count]) => {
    sumBreakdown += Number(denom) * count;
  });

  let isVerified = false;
  if (sumInput === sumBreakdown) {
    isVerified = true;
  } else {
    throw new Error(`對帳失敗：輸入總額 (${sumInput}) 與面額拆解總額 (${sumBreakdown}) 不符！`);
  }

  return isVerified;
}
